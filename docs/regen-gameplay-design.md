# 回能快递员：能量回收玩法设计

日期：2026年11月11日  
状态：首版玩法已接入游戏。下文保留设计意图，实际实现与验证范围见本页实施说明和根目录验收记录。  
定位：城市未来车厂「刹车充电秀」的玩法升级，3—6年级，单局约45—90秒，首次完整体验约6—10分钟。

### 2026年11月17日：霓虹快递闯关

默认入口改为三车道快递挑战：自动前进、左右换道、避让路障、收集徽章、轻刹减速送达、回能冲刺。夜市四站、山城下坡四站、午夜五站形成不同节奏；重玩更换后续目标车道。连续送达增加奖励，漏送或擦碰中断连击，结束显示本趟得分、最高连击、星级和实际回收量。

绿色投递门要求对应车道及不高于约40 km/h；14–32 km/h完美送达。送达过半得一星、全部送达再得一星、零擦碰且至少两次完美送达获得第三星。停车实验的旧星级独立保留。

回收、摩擦、驱动、坡度与损耗由同一个功—能模型计算。额外冲刺用电不超过本趟已经回收的能量；储备条最多显示160 kJ。徽章和连击只增加游戏分数。低温和满电限制回收，摩擦制动补足相同的制动需求。主画面保留驾驶与反馈，细节放在可展开能量账本。原玩法由“停车与能量实验”入口继续访问，旧积分、作品与实验记录保留。

- 三条路线、四档控制、实际货物响应、站点交付、片段重试、教练示范与三种电池条件均已实现。驾驶示范约18 / 31 / 55秒，不含站间等待及查看对照的时间；原设计时长包含观察与重玩。
- 常驻车轮—电机—电池链路、点击电机原理说明、实时动能/回收功率/摩擦热、完整行程守恒账本、下坡高度输入已接入同一模型。同一次输入可重算回收与摩擦方案，也可只改变起始电池条件；回放从第一段有效回收附近开始，可拖动到任意时刻。
- 安全完成、货物平稳、净耗电三个星级已实现。策略比较要求同任务、模型与电池初态，且每站停车相差不超过1米。教练/练习/超速记录不参与手动星级和整趟策略比较；旧积分保留，新版手动纪录独立保存。
- 首版保存最近6趟、模式内最佳星级和最近一份带来源的能量发现，报告含电池输出、重力输入及真实分配。实时竞速幽灵车、装饰邮戳、多张收藏卡、额外音效与变化路线留待后续；当前使用实际同步回放、站点结果和现有提示音。

- 模型与浏览器自动试玩已实施；没有进行儿童用户测试，关于首次理解、愿意重玩及课堂节奏的判断仍需课堂试玩。

## 1. 玩家想做的事

**开着自己造的小车，把怕晃的快递送到城市各站；亲眼追踪运动中的能量怎样经电机回到电池，再用于下一次出发。**

快递提供行动目的；货物反应让操作有触感；回收链路与能量账本承担主教学内容。屏幕主标题为“回能快递员”，副标题明确写“动能回收挑战”。不同路线要求不同策略；每趟结束留下能复盘的能量结果。

第一轮的吸引点是：按下刹车后车身局部透视，车轮带动电机发电，能量流进入电池。第一份回收被写入真实账本，货物同时对速度变化作出反应。随后通过同一次刹停的开/关回收对照，先理解再生制动的价值，再在重玩中学习平稳驾驶与整趟节能。

### 科普主线：三个能亲手验证的问题

1. **能量从哪来？** 运动中的小车有动能；平路制动时动能减少，下坡还会有重力势能输入。
2. **怎样收回来？** 车轮经传动系统带动电机，电机工作于发电状态，电能经功率电子装置进入电池并以化学能储存。发电产生的制动力帮助车辆减速。
3. **为什么收不完？** 电机和电池有能力上限，转换有损耗；超出回收能力的制动需求由摩擦制动承担。

每个问题都由玩家的一次操作触发画面、读数和短反馈，知识卡用于进一步解释。

## 2. 主操作：一个有四个位置的驾驶手柄

小车沿固定道路自动转向，玩家只控制纵向运动。桌面与手机都使用同一条大手柄，支持点击位置或拖动，松手保持当前选择。

| 位置 | 车辆行为 | 玩家用它做什么 |
| --- | --- | --- |
| 行驶 | 电机供能，平滑加速到本段巡航速度，之后按实际阻力消耗能量维持速度 | 离站、通过较远路段 |
| 滑行 | 不请求驱动或制动；平路因阻力减速，下坡可能加速 | 提前收电门，利用已有速度靠近站点 |
| 轻刹 | 请求较小制动力；系统在能力范围内优先使用再生制动 | 缓慢减速、下坡控速、平稳靠站 |
| 重刹 | 请求较大制动力；回收不足的部分由摩擦制动补足 | 快到目标时修正，必要时及时停车 |

这是一个明确标注的教学车型：滑行档不带拖曳回收，轻刹/重刹由系统混合分配再生和摩擦制动。不同真实车型的松电门行为可能不同。

第一轮按「出发」平滑起步，只依次介绍滑行、轻刹、重刹；第二段再提示「行驶」。所有加速都真实扣除电量，不在站点之间偷偷补回能量。

键盘可用1—4选择对应位置，空格临时重刹，松开回到之前位置；仅在游戏操作区域处理快捷键，文字输入和其他控件保留本身行为。失焦、换页、触摸取消均清空临时输入并暂停，恢复前把手柄设为滑行，避免自动继续加速。另设独立暂停按钮。

**默认四档足够，连续力度作为后续进阶工具。** 四档让孩子先学会做决策；执行端平滑响应，避免一次按钮切换被视为无限大的冲击。

## 3. 三关要有不同的手感

### 第一关：布丁别晃！

教学任务副标题：**找回这次停车的动能。**

场景：给校园小店送一份布丁。平路、一个站点，货物放在有固定支架的透明盒里。

- 看见站牌，决定何时从行驶切到滑行，何时轻刹。
- 车速变化时，布丁产生可见的晃动；急变时小机器人扶住盒子，轻稳时逐渐恢复。
- 第一次产生有效回收功率时，车身局部透视，标明“车轮 → 电机发电 → 电池”；紧凑读数同时显示“动能减少 / 回收到电池增加”。完整链路在舞台下方可读，不要求孩子辨认车身上的小字。
- 完成第一次停车后，用这次真实输入生成“开启回收 / 仅摩擦制动”双车重放：相同初速、质量、道路与总制动需求，两车按相同轨迹停下，能量分配不同。
- 重放结束展示两份等尺度能量账本，明确指出摩擦制动路径中的一部分能量，在开启回收时转入了电池。对照中的数值由模型计算，不预写“节省百分比”。
- 停车定位点落入绿色区域且速度降为零，店员来收货，完成一次明确的交付。
- 刹早了可以低速挪到站点；刹晚了可以及时重刹。布丁晃动提供反馈，不因一次晃动就强制重开。
- 结算先回放本次最有代表性的回收片段，再提供货物晃动和停车位置复盘。下一次起步时能量流从电池流向电机，呈现“回收到电池的能量可以再利用”。

**好玩的地方：** 货物即时回应操作、停车有精度挑战、最后几米有修正空间、交付有角色回应。

**核心科普证据：** 同样完成一次停车，开启回收和仅用摩擦制动的能量去向不同。先建立“动能经电机转为电能”的认识，再讨论轻刹、重刹和回收上限。平稳不等于永远只用轻刹。

设计时长约45秒，驾驶部分与路长、速度一并校准。首次30秒内应完成最短教学交付。

### 第二关：下坡能量快递

教学任务副标题：**追踪下坡时能量的来源。**

场景：从山顶温室给山脚站送一株小苗。道路由缓坡、较陡段和到站平路组成，前方地形始终可见。

- 滑行进入坡道后，小车会因重力加速。
- 用轻刹控制速度；坡变陡时评估是否需要重刹，到坡底再减小制动力。
- 路边限速区和当前速度提示帮助预判。系统不靠直接钳制速度“自动过关”。
- 相同的轻刹输入，在不同坡段可能分别表现为减速、匀速或仍在加速，形成需要持续观察的操作挑战。
- 回收光流伴随实际电机发电出现；山顶到山脚的高度条逐渐降低，停车后解释能量来自高度下降。
- 能量链路增加“高度下降 / 重力势能减少”入口；匀速下坡回收时允许车速与动能大致不变，同时显示高度下降和电池能量增加，不伪造“动能一直减少”。
- 种苗弯曲与车速变化相关，轮胎和刹车盘反馈与模型一致。不增加短坡刹车“过热爆炸”等虚构故障。

**好玩的地方：** 连续调整速度的节奏、坡度变化带来的预判、回收流逐步积累的反馈。

**自然出现的科普：** 下坡时重力势能可以转为动能，再经电机部分回收；车不能无限回收，电机和电池都有能力上限。

设计时长约60秒。坡度、长度、车辆制动能力共同校准，所有条件下都有可行停车方案。

### 第三关：城市三站接力

教学任务副标题：**回收有上限，整趟怎样更省电？**

场景：送完三个包裹。第一站距离远，第二站很近，第三段经过缓坡。无需控制转向，也不加入突然冲出的行人。

- 较远路段可以行驶到合理巡航速度，再提前滑行。
- 两站很近时，可以较早切到滑行，避免先加到高速度再立即刹车。
- 下坡段结合第二关经验控制速度，最终完成三站交付。
- 一路保留真实电池账本：驱动用掉多少、回收多少、净消耗多少。只有安全完成同一任务的整趟记录才比较能效。
- 可在起步前选择常温、低温或满电；主链路显示接收状态以及摩擦制动何时补足。重玩时能够复现上一趟操作，只改变电池条件。
- 第一趟结束后，下一趟可显示自己上一趟的淡色轨迹；首版可用站点结果与操作片段代替实时幽灵车。
- 结算可能出现：“这一趟回收得更少，但总耗电也更少。”只在实际计算得到时展示，点击即可定位少了一次无必要加速的路段。

**好玩的地方：** 三次连续交付、远近站点的不同策略、与上一趟自己竞争、整趟任务逐步变顺。

**自然出现的科普：** 回收只能找回一部分已经付出的能量；少做无必要的加速和制动，往往更省电。

设计时长约90秒。不给越快到站越高分的奖励；设宽松任务时限防止无止境拖延，暂停时间不计入。

## 4. 电池状态成为“再玩一趟”的条件变化

常温、低温、满电仍是可选条件，不再分别充当三个相同操作的关卡。

- **常温：** 默认条件，建立对回收的直观认识。
- **低温：** 冬日快递，明确提示“电池接收能力受限”；同样制动时回收较少、摩擦制动占比更高。相同总制动需求仍应得到相同制动效果。
- **满电：** “这次已经满电了，还能回收吗？”初始没有充电余量时不能继续接收。摩擦制动正常工作；后续驱动消耗出余量后，可按照明确的SOC接收曲线恢复部分回收。

满电在有持续驱动的多站玩法中不能整局硬锁回收为零。该点取代首版固定满电上限为零的整轮处理方式。显示真实小幅SOC变化，不假装一次停车就充满电池。

每趟结束可点「换块电池，重放我的操作」：在同一路线、同一输入序列下重算三种条件。标为条件对照，不授予新的手动驾驶星级；功率条件改变可能影响后续SOC接收能力，照实呈现。

## 5. 一次体验的节奏

| 时机 | 玩家看到和做到的事 | 设计目的 |
| --- | --- | --- |
| 开始前约5秒 | 收到一份包裹和一句任务：“稳稳送到前面小店。” | 建立目的，避免先读一屏说明 |
| 起步后 | 车开起来，机器人提示一次“试试滑行” | 用动作学操作 |
| 第一次刹车 | 车减速，车轮带动电机发电，动能条下降，回收到电池的量增加 | 建立完整的能量转化链路 |
| 靠站 | 玩家继续调整，绿色定位区给出明确空间目标 | 留下技术操作空间 |
| 交付后 | 店员收货；首轮对照同一次刹停的两种能量去向，其他轮次回放最有代表性的科学现象 | 让奖励与学习证据一起回应刚才的行为 |
| 再出发 | 默认相同任务条件，提示上次最值得调整的一处 | 让重玩有明确方向 |

## 6. 游戏奖励如何服务学习

### 一趟三颗星

- **送达星：** 独立完成全部交付，停入区域并遵守任务中的安全速度条件；没有系统接管。
- **平稳星：** 已取得送达星，并满足该路线的货物晃动条件；按模型的减速度与变化率计算。必要的制动不被文案指责为“错误”。
- **节能星：** 已取得送达星，整趟净耗电达到同路线、同电池初态、同任务时限下的可行基准。比较净耗电，不以回收量排名。

平稳星和节能星可以分别取得，展示具体原因；个人最佳只升不降。低温和满电使用各自可达到的能耗目标，两者都能取得三星。

参与积分与挑战星级分开。维持现有100分、三种状态体验60分/手动停车技巧25分/能量探索15分的框架及奖励ID兼容，已获得的积分和体验章不减少。停车技巧按明确定义的模式内参考任务比较，辅助不替代新版手动最佳。

### 小而持续的成就

完成关卡获得布丁、温室、城市邮戳；额外保存三张带真实证据的能量发现卡：“动能变电能”“下坡能量有来源”“回收受限仍能停”。每张卡包含本人的一次操作、能量路径与数值，不以点过知识卡替代证据。邮戳贴到车辆快递箱或个人报告上，外观奖励不改变物理参数。

第一份有效回收显示“这次停车，找回了×× kJ”；这里使用实际进入电池的能量，不把显示值放大。再次出发时可短暂强调电池到电机的供能路径。完美靠站时店员挥手，回收停止时光流归零；没有全程遮挡视野的特效。

三关均可直接进入，邮戳不作为解锁下一关的门槛。三星可用于自我挑战，不设置班级强制排名。

### 没完成也有下一步

停早可继续低速靠站；错过站点或越界后暂停，指出原因，可重试当前路段。片段重试会把整趟标为练习，保留参与收益，但不与一次完成的整趟能效竞争。

「教练示范」和提示随时可用，遵守同一个模型。辅助、片段重试、系统兜底都明确写进记录，不传送汽车、不补发虚构能量。

## 7. 科普必须由玩法中的证据支持

### 常驻“能量透视舱”

舞台下方用一条紧凑且可读的结构图连接车轮、同一个电机与电池，并保留并行的摩擦制动支路。车身局部透视和结构图来自同一状态。

| 状态 | 必须看见的机械/能量关系 | 一句话反馈 |
| --- | --- | --- |
| 行驶 | 电池 → 功率电子装置 → 电机驱动 → 车轮，电池供能 | “电机用电，带着车轮转。” |
| 滑行 | 车轮继续转动，没有主动驱动或回收电流，阻力消耗运动能量 | “车还在动，但这时没有主动充电。” |
| 有效再生制动 | 车轮经传动系统带动电机，电机发电，经功率电子装置进入电池 | “小车的一部分动能，回到电池里了。” |
| 回收受限 | 电机/电池限制标记出现，摩擦制动支路实际增强 | “电池收不下的这部分制动需求，由刹车补上。” |

结构图的电机节点可点开近景，区分“驱动模式 / 发电模式 / 未主动回收”。箭头翻转表示能量方向改变；车轮与电机的机械旋转方向不为表现回收而反转。基本图简化功率电子装置，点击详情时显示逆变器/整流控制以及电池储存为化学能。

摩擦支路表达“车辆运动能量 → 刹车盘摩擦 → 热”，与回收支路并行；不能画成先进入电池再变成摩擦热。电机转换损耗和道路阻力归入另一项，不能误算成摩擦制动热。

### 把动能与电能变化同时显示

- 当前动能由车辆质量和速度计算，主标签写“运动中的能量”；精确值为kJ，展开才显示 `E_k = 1/2 mv²`。
- 在平路、无驱动的刹停片段中，用同一尺度显示：片段开始的动能 = 当前剩余动能 + 回收到电池的能量 + 摩擦热 + 其他损耗。条形分配随真实步进变化。
- 一次停完后继续显示该片段的终值，并指出回到电池的部分，避免只显示充电粒子却看不到能量减少的来源。
- 下坡不套用只有初始动能的账本，需要加入重力做功；完整行程还要加入电池驱动输出。不同来源明确分开，禁止把下坡累计回收除以小段初始动能后称为“回收效率”。
- 回收功率kW表示当前快慢；累计回收kJ或Wh表示总量，标签区分。一次刹车对动力电池SOC的变化很小，不以夸张的百分比增长制造效果。

### 两种用途的对照分开

- **解释回收原理：** 固定同一次制动输入与总制动需求，只切换“再生制动参与 / 仅摩擦制动”，比较电池增量与摩擦热；模拟车型保证足够的摩擦制动能力。对照展示教学替代方案，不指导用户关闭实车功能。
- **比较驾驶策略：** 使用同一路线和初态下实际安全完成的整趟记录，比较净耗电；不能仅凭某次刹车回收更多，宣布驾驶更省电。
- 若本次条件确实没有有效回收（如无充电余量），就展示差异为零及受限原因；不为教学效果强行生成回收。

| 要理解的概念 | 游戏中实际发生的证据 | 应避免的误解 |
| --- | --- | --- |
| 再生制动回收一部分能量 | 减速时电池能量增加，车辆动能减少 | 刹车可以凭空造电 |
| 回收有上限 | 制动需求超过回收能力时摩擦分支增加 | 只要轻刹就能100%回收 |
| 滑行与回收不同 | 滑行没有充电功率，但保持已有运动，可能少一次驱动和制动 | 回收数值最高就最省电 |
| 下坡有重力能量输入 | 高度降低与速度、回收、损耗同步计算 | 下坡充电违反能量守恒 |
| 电池条件影响回收 | 同一路线同一输入下，接收功率与能量分配发生变化 | 满电或低温导致汽车刹不住 |
| 摩擦制动有必要 | 需要更大减速度时及时补足制动需求 | 为了收电应该放弃及时停车 |

知识卡在交付后可选展开，每次只讲一句与本轮证据有关的话。报告只记录真实实验；单击“看懂了”不被当作已掌握知识的证据。

## 8. 画面与声音

- 沿用夜城与玩家车辆，侧视镜头在车前留足视野；道路、站点、坡度、货物是主画面。
- 主HUD优先显示下一站距离、当前速度、当前动能与回收状态；货物本身表达晃动，不另占一个大状态卡。能量透视舱紧邻舞台常驻，长知识说明折叠。
- 供能时从电池流向电机，回收时反向；橙色分支表示摩擦热。颜色与方向/文字共同表达含义。
- 第一关布丁晃动、第二关种苗轻弯、第三关包裹依次交付；物品动作读取相同车辆状态。
- 音效采用短促机械声、交付声与轻微回收音色；默认遵守已有静音设置。减少动效保留货物状态文字和能量数值。
- 手机驾驶手柄紧邻舞台，至少44px点击区域；不需要滚动页面才能找到制动。

素材以现有车辆SVG和程序绘制为主，新增三种货物、小店/温室/站点和机器人表情；先用清楚的矢量形状完成灰盒验证，再细化画面，不需要新增3D或实景照片依赖。

## 9. 实现边界与能量账本

继续使用 TypeScript + Vite + Phaser Canvas，DOM承载手柄、HUD和结算，模型与绘制分离。

`regen-model.ts` 管理纵向运动、驱动用电、阻力、坡度、混合制动、SOC、能量、投递与挑战规则；`regen-route.ts` 管理固定路线、站点与任务；`regen-view.ts` 承载界面与绘制；`regen.ts / regen.css` 负责输入、样式、回放与作品接入。

能量模型必须覆盖整趟行程：

- 从电池取出的驱动及辅助能量、回到电池的能量分别累计；净耗电为前者减后者。
- 初始电池能量 + 初始动能 + 初始重力势能，应等于当前电池能量 + 当前动能 + 当前重力势能 + 摩擦热 + 其他损耗。
- 电机驱动与回收均有损耗；加速再制动不能使同条件闭合过程的电池能量无故增加。
- 下坡若出现净充电，必须能追溯到高度下降等已计入的能量来源。
- 起步、站间加速、低速挪车、辅助控制全部遵守同一账本；抵达站点不重置SOC。
- 实际SOC限制剩余可接收能量；高SOC与低温降低接收功率。确切曲线为公开标明的教学参数，不宣称来自真实车型测试。
- 使用固定时间步长；行驶时巡航控制必须通过实际驱动力维持速度，不直接覆盖速度。
- 货物晃动是由纵向加速度驱动的简化阻尼模型；平稳条件使用过滤后的加速度/变化率，避免评分依赖动画帧率。
- 停车区域绘制和判定共用物理坐标；道路限速、超时及系统接管都保留原始记录。

只比较相同任务种子、模型版本、起终位置/速度、初始SOC/温度与时限的记录。更换任务参数会开始新的比较组。道路不开放无意义绕圈刷回收的捷径；所有时间与行驶损耗真实记录。

局部存档增加版本，保留旧积分和历史摘要；旧版缺少路线/驱动数据的记录不参与新版净耗电比较。保存最近6趟、最佳摘要和一组条件对照；截图与报告绑定同一轮次。

## 10. 制作顺序与试玩判断

1. **先做第一关灰盒。** 四档操作、一个站点、能量透视舱、同步动能/回收账本、同一次刹停的开关回收对照、布丁响应、交付/重试。验证玩家能否看懂“车轮带动电机发电”，以及是否愿意主动再来一次。
2. **做下坡模型和第二关。** 加入高度、重力、连续控速，先验证可解性和能量守恒，再做坡道美术。
3. **做三站路线和整趟比较。** 验证“少一次无必要加速，回收更少但净耗电也更少”的实际可行记录。
4. **接入电池变化、星级、作品和旧存档。** 校准每种条件的三星目标，完善键盘/触屏和离线导出。
5. **最后添加幽灵轨迹、外观邮戳与路线变化。** 路线变化只使用事先验证过的种子，同一轮比较中不暗改条件。

验收不以“功能都能点”为终点，还要观察：

- 初次试玩者能否在30秒内明白操作并完成最短交付；若普遍手忙脚乱，先减少同时出现的提示和路段事件。
- 玩家是否会在失败后说出具体下一步，如“早点滑行”“坡变陡时加一点制动”，而非只能猜按键时机。
- 第一关是否出现一次明显但可修正的晃动；第二关是否需要持续观察；第三关是否存在至少两种安全完成但耗电不同的策略。
- 玩家能否从自己的两次结果中发现回收量与净耗电的区别；由记录支持的解释才是学习证据。
- 初次完成第一关后，能否指出能量从运动的小车而来、经电机回到电池，并指出摩擦制动时能量会变成热；不能只记住“轻刹得分”。
- 开关回收对照保持同一停车轨迹，能量账本各自守恒；没有回收能力时如实显示零差异。电机转向与能量流向不混淆。
- 下坡匀速回收时，画面正确显示高度下降而不是强行降低车速或动能；能量透视舱、光流、账本、结果和报告读取同一记录。
- 低温/满电也能安全完成并取得三星；重刹在必要时不会被错误提示为不应该使用。
- 模型测试覆盖全过程守恒、SOC边界、满电消耗后的接收恢复、固定输入复现、星级、重试和旧存档；浏览器检查桌面、触屏、键盘、暂停和离线报告。

当前关卡参数已通过模型可达性与浏览器试玩；更进一步的难度、教学效果与课堂节奏校准仍需真实用户试玩。最终实现、离线文件与自动化证据见根目录验收记录。
