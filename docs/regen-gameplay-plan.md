# 能量回收玩法改进计划

日期：2026年11月11日  
状态：首版历史计划，尚未实施。任务、操作与能量模型已由[《回能快递员：能量回收玩法设计》](./regen-gameplay-design.md)更新；后续实施以新版为准。  
适用：现有「刹车充电秀」，面向3—6年级学生，沿用 TypeScript / Phaser Canvas、赛博朋克夜城画面与离线单文件。

## 1. 改进方向

> 新版方向：带着怕晃的货物完成校园靠站、下坡控速、城市三站接力。玩家控制“行驶 / 滑行 / 轻刹 / 重刹”；常驻能量透视舱展示车轮、电机、电池的转化链路，同一次刹停的开关回收对照解释原理。全程计算驱动用电、回收、SOC与重力势能，以安全送达、平稳和整趟净耗电评价。下文保留首次讨论记录；固定初速、整轮满电零回收、三种电池等同三任务等旧设定不再作为实现要求。

**让玩家通过控制刹车力度，亲手找到“停得准、刹得稳、回收更多”的方法。**

核心循环：观察停车区 → 调节刹车力度 → 看见能量分流 → 查看这次结果 → 改一种操作再挑战。

首次30秒内完成一次刹停体验；一轮操作、结算与重试约30—60秒，完整探索约5—8分钟。以上为体验设计目标，最终通过试玩校准。

## 2. 现版问题与对应改进

以下基于当前源码 `src/games/regen.ts` 的静态检查，未进行本轮浏览器试玩。

| 现状 | 对体验的影响 | 改进 |
| --- | --- | --- |
| 刹车只有按下、松开两档；松开仍有0.8 m/s²制动需求 | 主要猜刹车时机，力度不可控，松开的含义不够直观 | 引入连续力度；明确区分滑行、再生制动和摩擦制动 |
| 常温、低温、满电共用停车流程 | 换电池后缺少新的观察任务 | 设置入门、节能、条件对照三个任务 |
| 行驶中已有能量账本与回收光流，但结果数值还需额外展开 | 玩家难以发现操作如何改变能量分配 | 运行时显示分流，停车后自动展开实际能量结果 |
| 每种电池只保存最后一次结果 | 看不到自己这次比上次改进在哪里 | 保存有限轮次与匹配条件，支持操作前后比较 |
| 辅助停车也更新停车技巧最佳值 | 自动演示可以代替玩家取得技巧分 | 辅助保留体验收益，手动技巧与辅助记录分开 |
| 绿色区域按画布±90像素绘制，约等于±13.74 m；判定容差是±17 m | 视觉边界与实际判定不一致 | 区域、定位提示、评分读取同一份配置 |
| 报告使用固定的“我看见了电池状态不同……”总结 | 只玩过一种状态也可能显示比较结论 | 按实际完成的实验生成总结，有匹配记录才生成比较发现 |

## 3. 核心操作与反馈

### 一个主要控件：刹车力度条

- 舞台下方放置大尺寸力度条，范围0—100%，标出“滑行 / 轻刹 / 重刹”。指针位置决定力度，不依赖设备压力感应。
- 默认按住并拖动力度条实施制动，松手回到滑行。保留一个大刹车按钮：按住使用当前选定力度，松开释放；初始使用轻刹预设。
- 键盘空格按住刹车，方向键在力度控件获得焦点时调节力度。输入框、其他按钮和链接保留原有键盘行为。
- 提供“点击保持刹车 / 释放”作为免长按操作，以及独立的暂停按钮。暂停冻结模拟时间；恢复前显示当前力度。
- 失焦、隐藏页面、触摸取消、切换任务统一清除按住/保持输入并暂停，返回后由玩家继续。
- 第一轮短提示：“先轻轻刹，快停不住时加大力度。”提示只出现于相关时机。

### 让动作的后果直接可见

| 玩家操作或模型状态 | 画面反馈 | 帮助理解 |
| --- | --- | --- |
| 轻刹且电池能够接收 | 电机到电池的绿色光流，显示实际回收功率 | 部分运动能量回到了电池 |
| 制动需求超过回收能力 | 橙色分支流向刹车盘，盘面出现克制的热色 | 更强的制动需求由摩擦制动补足 |
| 低温限制回收 | 电池接收指示缩小，明确显示“低温限制” | 回收能力受电池条件限制 |
| 满电 | 电池入口显示“暂不接收”，绿色光流为零 | 没有回收仍可通过摩擦制动停车 |
| 停车完成 | 定位标记落定，能量账本展开，出现一句调整建议 | 知道下一轮可以改什么 |

舞台优先显示车速、到停车区的距离、累计回收量；完整参数放入折叠知识卡。光流粗细读取实际功率，账本面积读取实际能量。减少动效时保留静态箭头和数值。

电池百分比明确标为“起始电量”；本轮主要显示回收的kJ和占初始动能的比例。一次刹车带来的电量很小，不把电池动画夸张地充满。

## 4. 三个任务

第一版三个任务使用统一的起点、初速和停车区，便于对照；任务变化来自操作目标与电池条件。三个任务均可直接进入。

| 任务 | 玩家要做什么 | 重玩理由 | 核心发现 |
| --- | --- | --- | --- |
| ① 校园接送：停得稳 | 使用常温电池，学会轻刹、加力，停入绿色区域 | 更靠近中心，减少力度突然变化 | 制动力度与停车位置有关 |
| ② 节能车手：找回更多能量 | 在常温、相同初速和停车区下，尝试提前轻刹与较晚重刹 | 比较两次合格停车的回收比例和摩擦热 | 合理安排制动可以减少摩擦热，但停车要求必须满足 |
| ③ 电池侦探：同样刹车，结果为何不同 | 选择一条本人已完成的操作，分别用常温、低温、满电条件复现实验 | 收集三种真实能量账本，保存自己的发现；也可亲手驾驶各状态 | 电池接收能力改变能量分配，不应被表现成满电就无法刹停 |

第三任务直接使用记录的力度—时间序列重新运行模型，标注“复现我的操作”；不要求孩子凭手感重复一模一样的输入。没有可用记录时可先完成一次手动驾驶，或观看明确标注的示范。

辅助入口改为“看一次示范”，使用同一车辆模型自动制动。手动接管后本轮仍保留辅助标记。过晚接管导致无法停入区域时，如实展示结果。

## 5. 结算、星级与比较规则

### 结算只回答三个问题

1. **停得怎样？** 显示停早/停晚、距中心多少米、是否自己完成。
2. **能量去了哪里？** 显示回到电池、摩擦热、其他损耗的数值与比例。
3. **下一次改什么？** 根据实际记录给出一条建议，例如“这次刹得较晚，试着提前一点轻刹”；只有证据支持时才展示具体建议。

按钮为“按相同条件再试”“比较两次结果”“保存发现”。结果和个人最佳分开展示。

### 积分鼓励体验，星级表达挑战结果

- 维持现有100分结构：三种电池各20分体验，手动停车技巧最高25分，查看三种实际能量账本各5分。
- 体验章继续以完成任意一次刹停为准；停偏、辅助或操作复现实验均可留下明确标记的体验记录。
- 新版手动技巧只读取独立手动完成的最佳结果。已有积分与体验章保留，不把历史辅助成绩转为新版手动成绩。
- 观看自动展开的账本后点击“已看懂这次分配”记录探索行为；同一电池状态只计一次探索分。
- 挑战星级单独保存，不用回收kJ直接换积分，不设置跨电池状态的回收排行榜。

| 任务 | 一星 | 二星，需先满足一星 | 三星，需先满足二星 |
| --- | --- | --- | --- |
| 校园接送 | 手动停入区域 | 停入中心精确区 | 力度变化达到平稳条件 |
| 节能车手 | 手动停入区域 | 停入中心精确区 | 回收比例达到该场景已验证可达到的目标 |
| 电池侦探 | 完成一次手动有效停车 | 用同一输入完成三种电池对照 | 保存一条与这组实际结果关联的发现 |

停车外溢、超时或系统兜底停车不能获得手动停车星级，但保留体验与能量记录。满电没有回收比例门槛。

精确区、平稳条件和节能目标在模型阶段校准，并在开始前展示；基准使用同版本模型、相同车辆质量/初速/停车范围和真实可行的控制序列。回收目标不以理论100%为要求。

### 两种比较严格区分

- **比较驾驶操作：** 电池、初速、质量、道路和停车目标完全相同，变化项是刹车输入；两次都有效停入区域才标注“节能改进”。不合格停车仍可复盘，但不宣布节能获胜。
- **比较电池条件：** 同一输入序列、同一模型版本，只改变电池状态，展示三路能量分配。
- 每次比较记录来源轮次、条件和数值。没有匹配记录时引导再做一次，不拼接不相干的结果。
- 本轮失败不会覆盖个人最佳；最佳星级只升不降。

## 6. 模型与数据要求

### 把可复算模型独立出来

新增 `src/games/regen-model.ts`，承载配置、状态推进、制动力分配、终止判定、星级与比较资格。`regen.ts` 保留界面、输入、绘制和GameAPI接入。

- 将0—100%输入映射为制动需求；0%只施加明确的道路阻力。再生制动不足的部分由摩擦制动补足。
- 保留固定时间步进；为制动执行设置统一响应过程，避免按键预设因数值瞬跳天然无法获得平稳评价。
- 回收同时受电机制动能力、电池接收功率和转换效率限制；低速回收平滑衰减，接近停止时由摩擦制动补足。
- 每一步满足：初始动能 = 剩余动能 + 回到电池 + 摩擦热 + 其他损耗。最后一步把速度截断为零时仍必须正确分配能量。
- 同一输入下，三种电池的总制动能力保持一致；不同的是回收与摩擦的分配。
- 第一版以现有1300 kg、14 m/s和三种电池接收上限为校准起点。车辆皮肤不暗中改变教学参数。
- 绿色区域、中心精确区、定位点与成功判定共用配置，明确以车底的停车定位标记为判断依据。
- 超时、跑道越界采用同模型制动收尾，记录系统接管原因；终止前仍有速度的中断记录必须保留“剩余动能”。

### 保存真实记录并兼容旧数据

- 在能量游戏的局部记录中增加 `schemaVersion`，区分旧记录、手动轮次、辅助示范和操作复现实验。
- 新记录包含：任务、电池条件、模型版本、初始参数、输入序列、停车位置、能量分配、接管标记、星级与比较来源。
- 保留最近6次详细记录、各任务最佳摘要、最近一组有效比较。输入按变化记录，回放采样有明确上限，避免不断膨胀本地存储。
- 旧 `results / best / seen` 可展示为历史记录；缺少轨迹和条件的记录不参加新版公平比较。复用现有奖励ID及最高值更新机制，避免重复发分。
- 报告记录“我改了什么 / 出现了什么变化 / 我懂了什么”。尚未做过条件比较时，仅总结实际已完成的一次实验。
- 结算截图、结果与报告绑定同一个轮次，避免快速重开后保存错画面。

后续再考虑上一轮透明车轨迹、拖动时间轴回放、经可解性验证的停车位置变化。第一版的比较用并排结果与输入摘要即可，不依赖复杂回放界面。

## 8. 验收标准

- [ ] 常温下，两种不同刹车策略都能有效停车，并产生可解释的能量分配差异；节能目标存在稳定可达的操作。
- [ ] 同一控制序列的常温/低温/满电对照可重复；满电回收为零，摩擦制动正常，停车位置符合模型预期。
- [ ] 全过程各能量项非负，初始能量账本误差不超过0.01 J；不同渲染帧率下结果一致到设定数值容差。
- [ ] 显示停车区与判定边界完全一致；边界内外、零速度、跑道越界和超时均有清楚结果。
- [ ] 鼠标拖动、触屏、键盘和点击保持均可完成；松手、取消、失焦、换页不残留输入；暂停期间不推进或累加时间。
- [ ] 辅助、复现和系统接管不产生手动技巧成绩；重复结算、回放、反复看账本不重复计分。
- [ ] 不同初速、目标或模型版本的记录不会被标为公平操作对照；满电可完成最高级任务要求。
- [ ] 旧存档、刷新、重进保留原积分；未完成轮次不显示通关；结果、截图、个人发现和报告指向相同实验。
- [ ] 320、390、1366、1920px下可见主要操作，无横向溢出；手机驾驶时无需滚动寻找刹车控件。
- [ ] 运行 `npm test`、`npm run build` 及能量游戏浏览器回归；用生成的离线HTML断网验证完整体验与报告导出。
- [ ] 首次试玩者能在30秒内理解如何刹车，并能说出“什么时候回收变少”；根据试玩调整提示与阈值。

本计划中的新增功能、阈值与验证项均未实施；实施时先完成模型校准，再确定最终挑战参数。
